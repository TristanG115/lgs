# LGS Visual Language

## Overall direction

LGS should feel like a mature developer tool with a subtle academic/paper
influence.

The paper aesthetic is an accent, not the interaction model.

Think:
- compact IDE tooling
- restrained research instrument
- high information density
- warm neutral surfaces
- precise typography
- subtle separators

Do not think:
- notebook simulation
- SaaS landing page
- AI startup dashboard
- student project
- whimsical research lab

## Branding

Keep branding minimal.

Prefer:
- L logo/mark
- optional compact "LGS"

Avoid:
- "Little Grad Student"
- "Research Lab"
- slogans
- capability marketing
- repeated product identity inside working surfaces

## Layout

Prefer edge-to-edge functional regions separated by subtle borders.

Avoid wrapping every region in a card.

Use whitespace to establish hierarchy, but keep the interface efficient.

The main conversation should receive most vertical space.

## Corners

Use modest rounding.

Typical guidance:
- buttons: 4–6px
- menus/popovers: 6px
- input composer: 6–8px
- status surfaces: 4–6px

Avoid highly rounded pill-shaped controls unless the shape communicates a
compact toggle/state.

## Typography

Use sans-serif for nearly all working UI:
- conversation
- controls
- metadata
- activity
- settings
- labels
- status

Serif may be used sparingly for a product accent or rare heading.

Do not use serif typography as the primary app UI font.

## Separators

Prefer thin borders and dividers over nested containers.

Good:
    Working · 4m 28s             Details
    ───────────────────────────────────

Bad:
    giant rounded status card inside another rounded card

## Icons

Icons must have a recognizable function.

Prefer standard VS Code/Codicon-style semantics where possible.

Do not introduce decorative icons merely to make the UI appear polished.

## Density

LGS should lean moderately dense.

The user is already inside VS Code and expects tool-like information density.

Avoid large empty vertical areas.
